# QA 점검: Phase 1 (UI 프로토타입) 끝

- 점검일: 2026-11-19
- 대상: `frontend/`, `.github/workflows/ci.yml`
- 방법: 코드 읽기. 테스트·빌드는 실행하지 않았고 마스터 전달 결과를 따른다. 브라우저는 열지 않았다.
- 표기: 통과 / 실패 / 확인 불가
- "API 변경 제안" 목록(2차 인증 재설정, setup 응답 필드명, 세션 목록 current, login/verify 204, 순서 변경, Source.is_default, due=upcoming 7일, topic_ids AND, 좋아요 PUT, POST /scraps liked)은 제외했다.

## 요약

Phase 1 완료를 막을 실패 항목은 **2건**이다. 둘 다 작은 수정이다.

- F-1: 링크 미리보기(제목 자동 채움) 실패 시 화면에 아무 안내가 없다.
- F-2: 프로덕션 빌드에 목 전용 "개발용" 섹션과 `?auth=`, `?fail=` 플래그가 그대로 들어간다. Phase 6에서 지울 대상이지만, 지금 `import.meta.env.DEV`로 가려 두면 안전하다. "Phase 6에서 지우기 쉬운가" 기준으로는 통과이고, 배포 빌드 노출 관점에서만 실패다. 필수는 아니고 권장이다.

나머지는 다음 Phase로 넘겨도 된다.

## 2. API 일치 (제안 목록 제외)

`src/api/index.ts`가 호출부를 한 곳에 모았고, 경로·메서드 주석이 API.md와 맞다. `GET /scraps` 쿼리 이름(`q, source_id, topic_ids, liked, due, sort, cursor, limit`), `/meta/preview`, `/ai/extract`(`text?`, `content_fetched`), `/ai/search`, 오류 형식 `{error:{code,message}}`(`http.ts`), `credentials: 'include'`가 모두 일치한다. 결과: **통과**.

API.md에 없지만 프론트가 가정하는 동작이다. 제안 목록에 없었으므로 API.md 확정 때 정해 주기를 권한다. 불일치라기보다 명세 공백이다.

| # | 가정하는 동작 | 위치 |
|---|---|---|
| A-1 | 출처 삭제 시 그 출처의 스크랩은 기본 출처("일반사이트")로 이동하고, 기본 출처는 삭제 불가(400). Source.is_default 제안과 관련 있지만 삭제 동작 자체는 명세에 없다 | `mocks/server.ts` mockSources.remove, `SettingsPage.tsx` deleteWarning |

### F-1 (실패, Phase 1 완료 전 수정): 제목 자동 채움 실패 시 안내 없음

- 위치: `ScrapEditorPage.tsx`의 `runPreview`. `preview.mutate`에 `onError`가 없고 `preview.isError`를 렌더링하지 않는다. `res.title`이 `null`인 경우도 조용히 넘어간다.
- 재현: 목 모드에서 `https://x.com/...` 또는 `daangn.com` 링크를 붙여넣는다(목은 이 출처에서 제목을 `null`로 돌려준다). 출처 배지만 바뀌고 제목은 빈칸이며 이유 안내가 없다. 네트워크 오류일 때도 같다(출처 "판별 중" 스피너만 사라진다).
- PLAN 점검 기준("제목 자동 채움 실패" 화면)과 API.md("실패 시 title은 null")에 해당한다.
- 수정 제안: 미리보기가 끝났는데 제목이 비어 있으면 링크 칸 아래에 `Notice warn` 또는 힌트로 "제목을 자동으로 가져오지 못했어요. 직접 입력해 주세요(비워 두면 링크 주소로 저장돼요)."를 보여 준다. `preview.isError`면 오류 문구도 보여 준다. 이 실패는 저장을 막지 않는다.

### E-1 (낮음): 주제·출처가 0개일 때

설정의 `ManageList`는 항목이 없으면 빈 테두리 상자만 보인다. 필터 칩 줄과 사이드바 섹션도 빈 채로 남는다. 새 설치 직후(주제 0개)의 상태다. "아직 주제가 없어요. 아래에서 추가해 보세요." 한 줄을 넣는 정도로 충분하다. Phase 5(주제 0개로 시작)에서 같이 처리해도 된다.

### E-2 (낮음): 좋아요 토글 실패 시 화면만 되돌아가고 안내가 없다

`useToggleLike`의 `onError`가 값만 복원한다. 사용자는 하트가 되돌아간 이유를 모른다. Phase 6 연동 때 토스트나 한 줄 안내를 넣는다.

### E-3 (Phase 6 메모): 인증 상태 오류 처리

`AppLayout.tsx`는 `useAuthStatus()`가 오류(네트워크 실패)일 때 가드 없이 앱 틀을 그대로 렌더링한다. `http.ts`에는 401 응답을 받으면 로그인 화면으로 보내는 처리가 없다. 목 단계에서는 문제가 없고 Phase 6 항목이다.

| `.gitignore` | 통과 | `node_modules/`, `frontend/dist/`, `*.tsbuildinfo`, `.env*`, 복구 코드 등 확인. `frontend/` 안에 `.env*`, `dist`, `node_modules`가 추적될 위험은 없음(루트 `.gitignore`가 덮음) |
| XSS 방어 (목 데이터에 `<script>`, `javascript:` 포함) | 통과 | `skipHtml` + URL 화이트리스트, 상세의 URL은 `safeHref`, `rel="noopener noreferrer"`. 시드 데이터에 일부러 공격 문자열을 넣어 확인하게 한 것은 좋다 |
| 이 QA 문서 자체 | 통과 | 비밀·실제 값 없음. `qa-*.md`는 `.gitignore` 대상이 아니라 커밋된다 |

### F-2 (권장): 프로덕션 번들에 개발용 섹션·플래그가 들어간다

## 9. 사람이 직접 확인해야 할 것

1. **실제 아이폰 Safari / 홈 화면 추가(PWA)**: 노치·다이내믹 아일랜드·홈 인디케이터 영역에서 상단 헤더와 하단 탭바·FAB·저장 바가 가려지지 않는지, 가로 모드에서 좌우 여백.
2. **`apple-mobile-web-app-status-bar-style: default`** 와 다크 모드 조합에서 상태 표시줄 글자가 읽히는지. `theme-color`는 다크 모드에서 `#18181b`인데 앱 배경은 `#141416`이라 색 띠가 보이는지.
3. **클립보드 "링크 붙여넣기" 동작**: iOS는 `readText()`를 호출하면 "붙여넣기 허용" 팝업이 한 번 뜬다. 허용·거부·빈 클립보드 세 경우의 안내 문구, 거부 후 입력칸 길게 눌러 붙여넣기가 되는지. HTTPS에서만 동작하므로 Phase 2 이후 실도메인에서 다시 확인한다(로컬 http 접속에서는 다를 수 있음).
4. **다크 모드 대비**: 시스템 설정을 다크로 바꾼 뒤 `--c-muted`(#a6a6b0) 글자, 배지(warn/danger/accent-soft), AI 제안 점선 박스, 비활성 버튼(`opacity-50`).
5. **iOS 입력 포커스 시 레이아웃**: 편집 화면에서 키보드가 올라올 때 sticky 저장 바 위치, 마감일 `<input type="date">` 모양과 폭, 6자리 코드 입력의 숫자 키패드와 SMS 자동 입력(`one-time-code`).
6. **긴 제목·긴 URL·메모 수백 줄**일 때 목록 카드와 상세가 깨지지 않는지(카드는 `line-clamp-2`, URL은 truncate).
7. **768~1023px(태블릿/좁은 데스크톱 창)**: 사이드바 + 전체 폭 목록, 상세가 전체 화면으로 열리는 동작이 의도한 디자인인지.
8. 데스크톱 1280px에서 사이드바·목록·패널의 스크롤이 각자 따로 움직이는지(`lg:h-dvh lg:overflow-y-auto` 구조라 브라우저 창 높이에 의존).
