### 5-2. 불일치 / 명세 공백

- [권장] **R-1. API.md 표(125~128행)의 "GET/POST/PATCH/DELETE `/sources`, `/sources/{id}`"와 달리 `GET /sources/{id}`, `GET /topics/{id}`는 구현되지 않았다.** `sources.py` 162~244행, `topics.py` 44~89행은 목록 GET만 있고, 단건 GET은 405다. 프론트(`api/index.ts`)도 단건 조회를 쓰지 않으므로 코드가 아니라 문서를 고친다: "GET은 목록만"이라고 표를 나누거나 `GET /sources`, `POST /sources`, `PATCH/DELETE /sources/{id}`로 풀어 쓴다.
- [권장] **R-2. "나머지 `/api/*`는 세션 필수"(API.md 67행, 133행)와 미등록 경로의 동작이 다르다.** 로그인하지 않고 `/api/nope`를 부르면 401이 아니라 404 `not_found`다(`tests/test_app.py` 18행 `test_unknown_path_404`가 이를 고정). 등록된 라우트는 전수 검사로 모두 401이므로 실질 영향은 없다. 문서에 "등록되지 않은 경로는 404"를 한 줄 넣거나 동작을 바꾼다. 바꾼다면 `test_unknown_path_404`의 `/api/nope`도 함께 수정.
- [참고] `GET /scraps/abc`처럼 숫자가 아닌 경로 id는 404가 아니라 400 `invalid_input`이다(FastAPI 경로 변환). API.md "없는 id는 404"와 충돌하지 않는다(없는 id가 아니라 형식 오류). 문서에 한 줄 적어 두면 Phase 6의 오류 화면이 헷갈리지 않는다.
- [참고] API.md는 `domain_patterns`의 호스트에 소문자 영문·숫자·`-`·`.`만 허용한다고 쓰는데 한글 도메인(`예시.한국`)은 패턴으로 넣을 수 없다. 판별은 URL 쪽을 IDNA로 바꿔 비교하므로(`sources.py` `_host_forms`) punycode(`xn--...`)로 입력하면 동작한다. 의도한 제한이면 문서에 한 줄(퓨니코드로 입력).
- [참고] 커서는 필터(`q`, `liked` 등)에 묶이지 않는다. 필터를 바꾼 뒤 이전 커서를 쓰면 오류가 아니라 "그 위치 이후"의 결과가 나온다. 프론트는 필터가 바뀌면 커서를 버려야 한다(7절).

## 7. Phase 6 이후로 넘길 것

Phase 6 (프론트 연동) 체크리스트에 추가할 것:
1. 목 데이터를 실제 API로 바꾼 뒤 목의 출처 목록(6개, 커뮤니티 패턴, 깃허브)을 서버 시드(5개)와 맞추거나 목을 삭제한다. 개발 중 목을 쓰는 경로가 남으면 서버 기본값과 같은 데이터로 둔다.
2. 오류 코드 매핑을 서버 기준으로 다시 쓴다: `invalid_input`(메시지는 서버 문구를 그대로 표시), `duplicate_name`, `duplicate_pattern`, `default_source`(403), `not_found`, `db_unavailable`, `too_many_requests`. 목 전용 코드(`invalid_url` 등)를 화면에서 참조하는 곳을 찾아 제거.
3. 페이지 이동은 `next_cursor`를 그대로 저장해 `cursor`로 보내고, 필터·정렬·검색어가 바뀌면 커서를 버린다. `limit`은 필요하면 명시(기본 30).
4. `PATCH /scraps/{id}`에는 `ScrapPatch`에 있는 필드만 보낸다. 상세 화면의 `Scrap` 객체를 그대로 펼쳐 보내면(`id`, `source`, `topics`, `created_at`, `liked` 포함) 서버가 400을 돌려준다. 폼은 `source_id`, `topic_ids`로 변환해서 보낸다. 좋아요는 `PUT /like`로만.
5. 저장 동선: 링크 붙여넣기 → `POST /meta/preview` → `title`이 `null`이면 빈칸으로 두고 사용자가 입력(서버는 빈 제목을 URL로 저장), `source_id`를 출처 선택에 반영(사용자 변경 가능). 미리보기는 최대 5초 걸릴 수 있으므로 입력을 막지 않는 로딩 표시가 필요.
6. `due` 판정의 "오늘"은 서버(Asia/Seoul) 기준이다. 프론트의 "마감 임박" 배지도 같은 기준으로 계산(자정 부근 기기 시간대 차이).
7. 마크다운 메모·원격 제목 렌더링, 표시용 URL 처리 규칙은 별도 문서(비공개)의 항목을 `ui-builder` 지시에 반영.
8. 설정 화면 출처 관리: 패턴 입력은 호스트 이름만(`youtube.com`), 다른 출처와 중복이면 `duplicate_pattern`을 필드 오류로 표시. 기본 출처는 삭제 버튼 숨김(서버는 403).
9. 목록이 비었을 때(스크랩 0개)와 필터 결과가 없을 때를 구분한 빈 상태 화면, 목록·미리보기 실패 시 재시도 화면(Phase 1 QA에서 이미 설계된 항목).

- 로컬에서 `ENABLE_API_DOCS=1`로 서버를 띄우고(README 순서) 가입·로그인 후 실제 URL로 `/api/meta/preview`를 호출한다: 일반 사이트(`og:title`), 유튜브 영상(oEmbed), 로그인이 필요한 페이지(null), 존재하지 않는 도메인(null), `http://127.0.0.1:8000/`(null, 내부 주소 거부). 테스트는 가짜 네트워크이므로 실제 외부 사이트와의 호환(TLS, 리다이렉트, 인코딩)은 사람이 본다.
- 실제 한글 데이터로 검색: 2글자("공모"), 3글자 이상("공모전"), 영문 대소문자, 주제 이름, URL 일부, 띄어쓰기 단어 AND.
- 스크랩 수백 건을 넣고(스크립트) `limit=30`으로 `sort=due`와 `sort=created` 끝까지 순회, 응답 시간 확인(인덱스 `scraps_created`, `scraps_due` 사용 여부는 `EXPLAIN QUERY PLAN`으로).
- 운영 배포 후(병합·승인 뒤): 첫 배포에서 마이그레이션 0003이 적용되고 `/api/health`가 통과하는지, 배포 직전 백업이 FTS 테이블이 있는 DB에서도 성공하는지(Phase 4 배포 이후 처음 FTS5 가상 테이블이 들어간다). 롤백이 일어났다면 `docker logs`의 마이그레이션 오류 줄(값 노출 없는 형태)을 본다.
